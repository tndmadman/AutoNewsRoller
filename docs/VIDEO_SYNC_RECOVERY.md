# Video synchronization recovery

The renderer uses the final mixed audio stream's duration ticks and time base to calculate a single integer frame budget. Weighted cumulative boundaries reserve at least one frame per scene; impossible scene counts fail explicitly. Every scene is trimmed by frame count, the concatenated clock is reset to frame index, output CFR is explicit, disclosure ends with the video, and audio is no longer cut by shortest-stream termination.

Settings (worker configuration): videoSyncRepairEnabled=true; videoSyncRepairMaxMismatchSeconds=2.0 (0–2); videoSyncRepairMaxAttempts=2 (0–2). A complete audio stream is mandatory. Eligible visual duration/frame-count mismatches can be trimmed or extended by cloning the already-composed final frame, with original AAC copied. Repair uses NVENC if the initial render used NVENC; x264 is the fallback. It verifies the candidate before atomic replacement and never creates approval metadata. Unsupported atomic replacement fails closed. Normal pipeline audit and content safety remain independent and subsequent. Sync metrics are included in audit.json and progress events.

Source audio checks use a codec packet allowance (1024 samples plus 2 ms); timing metadata does not prove semantic equivalence of narration. The normal target is one video frame, with AAC timestamp quantization allowance. Existing 350 ms audit limit remains unchanged.

Run VideoAuditSelfTest (which also runs VideoRendererSyncSelfTest) with FFmpeg and FFprobe available. Test on an isolated Windows worker with NVENC, then x264, before updating production. Drain workers and update controller and worker to the same validated branch revision. A failed repair retains its original render; existing jobs may be retried through the existing operator workflow. Historical cache recovery is not implemented here. A synthetic 1084-frame/35.550s fixture represents the reported duration mismatch; exact historical production cause remains unconfirmed without its actual assets and command.

Per-render FFmpeg logs (`video.mp4.render.log`, optional fallback log), per-attempt logs and `video.mp4.sync.json` are written next to the intermediate render. The JSON records before/after stream metadata, attempted commands, bounded failure reasons and timing. Interruptions terminate FFmpeg, retain the original output and remove the temporary repair artifact. The test suite includes short 24/25/60 FPS motion/overlay/caption cases, duration allocation matrix, disabled and out-of-limit repair, cancellation, and source truncation rejection.
